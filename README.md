## Track
Pixels to Products: turning images (reports, IDs, auto-generated cards) into a working real-world product, with Cloudinary doing the image work.

## The problem
In an emergency, a family that needs a specific blood group urgently has to call many places and ask around. Finding a compatible, eligible donor nearby is slow and stressful, and fake or stale requests waste donors' time.

## The solution
Blood Network is a public-first, real-time emergency blood matching platform. It connects donors, patients, hospitals and blood banks.

1. A patient's family creates an SOS: blood group, units, area, urgency.
2. The system finds compatible, eligible donors nearby and ranks them (blood-group compatibility, distance, verification, last-donation gap, urgency radius).
3. The best matches get an instant alert.
4. Live status: Searching, Donor Found, Contacted, Donation Coordinated, Completed.
5. The donation itself always happens at an authorized, licensed blood-collection facility. No blood is exchanged privately. Hospitals and blood banks are the intended secondary users.

### Safety and trust features
- **Escalation engine:** if no donor accepts within 10 minutes (set `ESCALATION_MS` to change), the search radius doubles, more donors get in-app alerts and nearby blood-bank alerts are simulated (recorded in the timeline only; no real message is sent). Timeline shown on the request. The "Simulate 10 min" button triggers it instantly for demos.
- **Donation cooldown:** whole blood 90 days, plasma 28 days, platelets 14 days. Donors in cooldown are never matched; donating via the app starts the cooldown.
- **Contact masking:** nobody's phone number is shown or sent to the browser. Requester and donor talk through a platform relay chat after the donor accepts.
- **Fraud checks:** duplicate requests (same patient, group, area, number within 6 hours), 3+ requests from one number, and any mention of money or payment are held for review with no alerts sent. Messages that mention money get a warning. Two user reports ("asked me for money / fake") flag a request or donor and remove them from matching.
- **Platelets and plasma:** requests can ask for whole blood, platelets or plasma. Plasma uses reverse ABO compatibility (AB donors are universal), each type has its own cooldown.

The goal is to cut the time and friction of finding a compatible donor. It does not try to bypass hospitals.

## How we use Cloudinary
| Feature | Where | Why |
|---|---|---|
| **Signed server-side Upload API** (`cloudinary.js`, `upload()`) | Donor government-ID photo, patient medical report / doctor's slip | Images are stored in folders `blood-network/donor-ids` and `blood-network/medical-reports`; API secret never reaches the browser |
| **On-the-fly text-overlay transformations** (`requestCardUrl()`) | Emergency request card | Every SOS gets an auto-generated, shareable card (blood group, units, area, urgency, patient, hospital, request ID) built entirely from a delivery URL, to forward on WhatsApp |
| **`e_blur_faces`** (`thumbUrl()`) | Donor ID thumbnails in the public view | Privacy: faces on ID photos are blurred in the public donor view |
| **`f_auto,q_auto`, `c_fill`** | All delivered images | Smaller images on slow mobile networks |

Without credentials the app runs in demo mode: cards are still generated by Cloudinary (public `demo` cloud), and uploads fall back to the local data URI. Set the env vars below for real uploads.

## Run it
Needs Node 18+. No dependencies to install.
```bash
git clone <this repo> && cd <this repo>
# optional - real Cloudinary uploads
export CLOUDINARY_CLOUD_NAME=your_cloud CLOUDINARY_API_KEY=xxx CLOUDINARY_API_SECRET=xxx
# optional - branded card background uploaded to your cloud
export CARD_BASE_ID=your_template_public_id
npm start        # http://localhost:3000  (works on a phone on the same Wi-Fi)
```

## How to test
Unit tests (compatibility, plasma rules, per-type cooldown, ranking and radius, escalation timing, fraud flags, Cloudinary URL building):
```bash
npm test
```
Manual demo (2 minutes):
1. Open the app, tab **SOS**: patient "Rahul", B+, 2 units, Gachibowli, Critical, any 10-digit number, then **Find donors now** (the **Fill demo** button pre-fills a sample case).
2. See the Cloudinary-generated emergency card, ranked matched donors, and "donors alerted" on the live tracker.
3. Tab **Donors**: pick an alerted donor in the alerts inbox to see the notification, tap **I can donate**, then chat via the platform relay.
3b. Tick **Platelets** or **Plasma** in the Need grid to see different matching. Press **Simulate 10 min with no reply** on a request to see the radius widen and simulated blood-bank alerts appear in the timeline. Submit the same request twice to see the duplicate flag (tab **Safety** shows the review queue).
4. Tab **Donors**: register a donor with an ID photo (stored as a private Cloudinary asset; the public view shows only a face-blurred thumbnail and the label 'ID uploaded (not verified)' - no identity check is performed).
5. Back on tab **SOS**: move the request through Contacted, Donation Coordinated and Completed.

## Deploy
A `Dockerfile` and `render.yaml` are included. Create a Render (or Railway/Fly) web service from this repo and set the three `CLOUDINARY_*` variables. Data is kept in a local `data.json` by default, which Render's free disk wipes on every restart/redeploy. For persistence, create a free Upstash Redis database (no card) and set `UPSTASH_REDIS_REST_URL` and `UPSTASH_REDIS_REST_TOKEN`; the whole app state is then saved there and reloaded on start.

## Voice Helpline (Hinglish) - powered by Gnani AI

Callers can ask for blood by voice in Hinglish/Hindi instead of filling a form:
"O positive chahiye Dilsukhnagar me urgent" -> the helpline transcribes the speech
with **Gnani Prisma (speech-to-text)**, extracts blood group + area + urgency,
matches donors with the existing matching engine, and speaks the answer back with
**Gnani Timbre (text-to-speech)**.

- Page: `/voice` (mic recording + audio-file upload)
- API: `POST /api/voice/helpline` with `{ audioBase64, mimeType, language? }`;
  `GET /api/voice/status` reports whether the key is configured.
- Setup: set `GNANI_API_KEY` on the server (never commit it). Optional overrides:
  `GNANI_STT_LANG` (default `hi-IN`), `GNANI_TTS_LANG`, `GNANI_TTS_VOICE` (default `Nalini`).
  Without the key the rest of the app is unaffected and the endpoint returns 503.
- Parsing is rule-based (`voice-parse.js`, unit tested) and understands Roman
  Hinglish and Devanagari transcripts, spoken blood groups ("oh positive", "बी नेगेटिव"),
  Hyderabad area aliases (KPHB, Sikandarabad, ...), components and units.
- **Demo data only**: matches come from the app's synthetic seed donors and the
  spoken reply says so. Do not demo with real people's data.
- Built with AI assistance (Claude) for the Gnani AI Internship Challenge;
  contribution is declared in the project description.
